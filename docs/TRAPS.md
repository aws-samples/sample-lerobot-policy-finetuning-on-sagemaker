# Traps this repository guards against

Each row names something that went wrong once while this sample was built, the stage that now catches it, and the test
that proves the catch. Three terms come up often. The registry is the set of per-policy files in `trainer/policies/*.yaml`;
each one holds the command line (argv) the trainer renders for that policy. Preflight is the set of checks
`pipeline/preflight.py` runs before a job is submitted. A smoke run is a short training job (200 steps; the CPU version
runs 20) that checks the whole path end to end before a long run.

| trap | where it is caught | proof |
|---|---|---|
| `action` is bit-for-bit identical to `observation.state` (a recording of nothing: the policy learns to hold still) | `check_dataset.py` scans every data file and FAILs unless `--force-action-eq-state` is set | tests/test_check_dataset.py |
| `action` is an exact copy of `observation.state` shifted by k frames | WARN in `check_dataset.py` | tests/test_check_dataset.py |
| EO-1 passes its image budget (`image_min_pixels` / `image_max_pixels`) to `apply_chat_template` as plain keyword arguments. transformers 5.5.4 warns on every step (`Kwargs passed to processor.__call__ have to be in processor_kwargs dict`), but in 5.5.4 the recommended `processor_kwargs={...}` form is ignored for the budget (measured: 469 instead of 261 visual tokens for two 360x480 frames). Following the warning would silently raise EO-1's token count and memory | `amp_driver.py` silences the warning and leaves lerobot's call unchanged. A Docker-marked test measures both forms in the pinned image and fails when a transformers upgrade changes which one applies ([docs/TESTING.md](TESTING.md), Docker lane) | tests/test_eo1_pixel_budget_docker.py |
| `action.names` is exported as a dict `{"axes": [...]}` instead of a flat list of joint names; policies that read the names break ([docs/RECORDER_CHECK.md](RECORDER_CHECK.md) explains the effect) | WARN by default; FAIL with `--require-flat-names`, which `pipeline/run.py` and `train_policy.sh` add when an enabled policy's registry entry sets `requires_flat_action_names: true` (today groot and molmoact2) | tests/test_check_dataset.py |
| ACT has no resize step: 720×1280 videos must be downscaled first | the job runs `prepare_dataset_360.sh` before training; it keeps the aspect ratio and checks that frame counts match | `scripts/smoke_aws.sh` (the CPU smoke job on SageMaker; [docs/TESTING.md](TESTING.md)) |
| cameras that are not 16:9 get squashed to 640×360 | `downscale_plan.py` keeps the aspect ratio (480×640 becomes 480×360) and warns | tests/test_downscale_plan.py |
| datasets stored as PNG frames (feature dtype `image`) fail inside the job | FAIL in `check_dataset.py` | tests/test_check_dataset.py |
| torchcodec cannot load in the SageMaker Deep Learning Container base image (its Python is statically linked) | removed from the image; PyAV decodes video; `--dataset.video_backend=torchcodec` is refused as a forbidden flag | build-time checks in `trainer/sagemaker/image_asserts.py`, tests/test_registry.py |
| lerobot refuses to start when `--output_dir` already exists; the `last` symlink breaks after a round trip through S3 | the trainer writes to `OUT_DIR/train`, repairs `last`, and publishes the newest numbered checkpoint | tests/test_summary_publish.py |
| `--policy.*` flags together with `--resume` crash lerobot | resume renders only `--config_path` + `--resume=true` (extend also adds `--steps`), plus any overrides that are not `--policy.*`; `--policy.*` overrides are dropped with a note on stderr, see the resume row of [docs/ARCHITECTURE.md](ARCHITECTURE.md) | tests/test_registry.py |
| extending a run whose scheduler decays the learning rate continues at the floor (the lowest rate the decay reaches) | extend adds `--scheduler.num_decay_steps` only for policies whose registry entry declares a scheduler (ACT uses a constant learning rate) | tests/test_registry.py |
| ACT downloads ResNet18 from torch.hub when the model is built, even offline | the weights are staged in the image; `reload_check.py` loads the published checkpoint offline with an empty cache | the `reload_check` key of the smoke job's SUMMARY.json, written by `trainer/reload_check.py`; the smoke gate in `pipeline/run.py` fails when it reports `ok: false` |
| `--policy.dtype=bfloat16` stores the weights themselves in bfloat16, which keeps only 8 bits of precision; AdamW updates smaller than that are rounded away and training silently stalls | forbidden flag; the smoke check asserts zero trainable bf16 parameters | tests/test_registry.py (forbidden flag), tests/test_run.py::test_smoke_gate_rules (zero-bf16 gate), AWS smoke |
| a flat 8 h runtime cap stops a run on a slow GPU before it publishes | the cap is derived from the measured step rate times a multiplier (`sm_jobs.max_runtime_seconds`) | tests/test_sm_jobs.py |
| SageMaker sends SIGTERM when you stop the job, when the runtime cap is hit, or when a Spot instance is reclaimed; without a handler the job ends with an empty model.tar.gz | the entrypoint's SIGTERM handler publishes the newest checkpoint with `status=interrupted` and exits 143 ([docs/ARCHITECTURE.md](ARCHITECTURE.md), container flow) | tests/test_entrypoint_sigterm.py |
| instances with several GPUs cost 2.5 to 4 times more, and the trainer is a single process | preflight refuses more than 1 GPU unless `--allow-multigpu` is set | tests/test_preflight.py |
| Spot capacity has its own quota name; a job with quota 0 fails at submit time | preflight checks one quota name per candidate instance type: the on-demand name by default, the Spot name instead when Spot is requested (the smoke and the training job use the same capacity type); CPU staging jobs always use the on-demand name | tests/test_preflight.py |
| the dataset bucket is in a different region from the job | preflight compares the bucket's location, the image's region and the session's region | tests/test_preflight.py |
| lerobot prints `step:8K` and uses carriage returns; a naive grep reports a frozen run | the trainer pipes its output through `tr '\r' '\n'`; the step parsers read lerobot's rounded labels (`step:8K` = 8000); whether a job is alive is judged from the newest `checkpoints/<step>/` object in S3, never from the metric line alone (`pipeline/logs.py`) | tests/test_summary_publish.py, tests/test_preflight.py |
| `TQDM_DISABLE=1` does not turn off lerobot's progress bar (lerobot passes its own explicit flag) | the same `tr '\r' '\n'` pipe in `trainer/train_policy.sh` | seen in the smoke job's CloudWatch log; covered by the tests of the row above |
| a 200-step smoke run is worse than the hold-still baseline (a policy that predicts the arm stays where it is); a gate that required beating it would always fail | the smoke gate never uses beats-hold | tests/test_run.py |
| AWS can re-point the base image tag, and an unpinned `pip install` can resolve different package versions on each build | `trainer/sagemaker/Dockerfile` pins FROM by digest and installs against `trainer/sagemaker/requirements.lock` (LOCK_MODE=enforce fails the build on any drift) | trainer/sagemaker/Dockerfile; the CDK stack builds it on CodeBuild |
| `lerobot[groot]` pulls in a decord wheel that fails `pip check` on Python 3.12 | the `groot` extra is not installed; GR00T's actual dependencies (dm-tree, timm, peft, transformers, diffusers) are installed explicitly | `trainer/sagemaker/image_asserts.py` asserts at build time that neither torchcodec nor decord imports |
| `push_to_hub` stamps apache-2.0 on any fine-tune that has no licence of its own | `--policy.push_to_hub=false` in every registry argv | tests/test_registry.py |
| the AWS CLI prefers `AWS_REGION` over `AWS_DEFAULT_REGION`; a script that sets only one deploys or lists in the wrong region | every boto3 session pins `region_name`; the README says export both | tests/test_aws.py |
| account ids, bucket names or private names leaking into a public repo | `scripts/scrub_check.sh` in CI: it fails on any 12-digit account id (decimal numbers and hex digests are ignored), access key, token, private address, internal hostname, EC2 id or CDK bucket name in a tracked file and on a tracked `local_folder/`; `--history` scans every commit of every ref before a public push; maintainers' local runs also match the private, git-ignored `.scrub_denylist`; the pre-commit hook install is in [docs/SECURITY.md](SECURITY.md), Secrets and identifiers | tests/test_scrub.py |
| the smoke's steps/s overstates what a training job delivers per billable second, because billable time also covers start-up (container start, dataset and hub-cache copy, model load), evaluation and checkpoint writes | `compute.runtime_multiplier` (default 3.0 in `sm_jobs.max_runtime_seconds`, headroom for a slower fallback instance or a heavier dataset; both example configs use 1.5); a capped job continues with `--resume-from <job>` from its last mirrored checkpoint | tests/test_sm_jobs.py::test_derived_runtime_and_volume; measured ratios in the sizing paragraph of [docs/RESULTS.md](RESULTS.md) |
| a converter leaves cameras out of `meta/stats.json` (seen with a third-party v2.1 to v3.0 export); lerobot-train reads `stats[<camera>]` to apply the ImageNet mean/std and stops with a KeyError in `make_dataset` | `check_dataset.py` WARNs for each missing camera; before training, `ensure_quantiles.py` writes a metadata-only copy of the dataset whose `stats.json` has an ImageNet mean/std entry for each missing camera, and the job trains from that copy (this runs for every policy) | tests/test_check_dataset.py, tests/test_ensure_quantiles.py |
| lerobot's own `convert_dataset_v21_to_v30` fails on per-episode H.264 videos with `non monotonically increasing dts to muxer` while it concatenates the episode files | nothing in this repo catches it; re-encode the per-episode videos at a constant frame rate first (`ffmpeg -c:v libx264 -g 2 -pix_fmt yuv420p`) or export directly in the LeRobot v3.0 format from your recording software; the converter command is in [datasets/README.md](../datasets/README.md), Older LeRobot exports | seen once, 2026-09-15, on a 158-episode 25 fps recording with lerobot 0.6.1; no automated test, the converter is upstream |
| a PEFT `target_modules` regex that names the wrong path matches nothing and the job stops at wrap time with `No modules were targeted for adaptation`. PEFT applies `re.fullmatch` to lerobot's real module names: FastWAM's attention projections live under `model.mot.layers.N.blocks.{video,action}.self_attn.{q,k,v,o}`, while `model.mot.mixtures.{video,action}` hold only embeddings and heads (a first `fastwam_lora` recipe with `.*mixtures\.video\..*\.(q\|k\|v\|o)` failed this way, 2026-09-18) | the smoke run fails before its first step, so the recipe never reaches a training job; the shipped `fastwam_lora` regex `.*\.blocks\.video\..*\.(q\|k\|v\|o)` is a golden value the registry test renders through the same code path as the trainer and checks with `re.fullmatch` against a video block name, an action block name and a mixtures name | tests/test_registry.py |
| merging a LoRA adapter into full weights on a CPU and saving the config used for that merge writes `device: cpu` and `use_gradient_checkpointing: true` into the served `config.json`; a server that loads it on a GPU fails with `Expected all tensors to be on the same device` (seen 2026-09-18 with a merged FastWAM checkpoint) | `publish.py` performs the merge for recipes with `publish.merge_adapter: true` and, before `save_pretrained`, sets `device` to the training device recorded in the adapter's `config.json`, `use_gradient_checkpointing` false, `use_peft` false and `pretrained_path` null; the merged copy is written to `pretrained_model_merged/` next to the adapter and `reload_check.py` reloads that copy without peft | tests/test_publish_merge.py |
| a LoRA adapter merge that builds the merged copy outside `/opt/ml/model` and renames it in: `/opt/ml/model` is its own mount on SageMaker (and a bind mount on an EC2 host), so `os.replace` fails with `EXDEV` and the publish records `merge_error` instead of a merged checkpoint (p5.4xlarge smoke, 2026-09-21) | `publish.py` `_scratch_dir()` creates the scratch directory as a hidden sibling inside the model directory (same filesystem, atomic rename); `maybe_merge()` removes leftovers of a killed merge before the next publish | tests/test_publish_merge.py |
| a reload check that blames sampling noise: the 2026-09-21 reloads of fastwam_lora checkpoints differed from their eval by 56-251 degrees and the recipe was marked `eval.stochastic`. The draw IS fixed by `inference_seed`; the spread was the untrained action encoder and head reached through FastWAM's alias (next row), whose base-side random init differs per process | `eval.stochastic` stays available for genuinely stochastic recipes, but no shipped recipe sets it: after the alias fix both FastWAM recipes reload with diff 0.0 (2026-09-22) | tests/test_registry.py |
| a PEFT `modules_to_save` entry that names a whole FastWAM expert (`"action"` = `mot.mixtures.action`): PEFT puts the trainable copy into the registered module tree, but FastWAM's `training_loss` and `infer_action` reach the expert through the unregistered alias `self.action_expert` (set with `object.__setattr__`), so the copy never sees a gradient and the alias keeps the base's untrained action encoder and head. Training "succeeds" (the LoRA and the per-layer action blocks do train), the saved copy is the default init, eval and reload score random heads that differ per process (the 20k run's 8.85 x hold; reload diffs of 56-251) | the recipe lists LEAF modules (`mixtures.action.action_encoder`, `mixtures.action.head`, the embeddings, `blocks.action`, `proprio_encoder`), so the swap happens on attributes the alias can see; `eval_openloop.load_policy` rebuilds the merged policy from its state dict | tests/test_registry.py |
