# Which public dataset fits which policy

`./finetune.sh --compat` answers this question for *your* dataset (see [README.md](../README.md)). This page records which
public LeRobot v3.0 dataset each policy was run on, why that dataset was chosen, and whether the run passed. A smoke test
is a 200-step training job that checks the setup before the real run. Dataset licences are yours to accept
([datasets/README.md](../datasets/README.md)); the licence check that runs before a job covers only the policy's base weights.

Errors below are given as "x hold": the held-out joint error divided by the error of the hold-still baseline, a policy that
predicts the arm stays where it is. Below 1.0 the policy has learned something.

Step rates, instance types, batch sizes, memory peaks and gate details of every smoke test and fine-tune are in
[docs/RESULTS.md](RESULTS.md). The four 80 GB smoke tests (`pi0_fast`, `eo1`, `fastwam`, `fastwam_lora`) ran on EC2 H100 hosts, because
no 80 GB SageMaker instance was available at the time. Those hosts used the same container, data channels and
hyperparameters as a SageMaker job.

Known defects of `hjkso1406/so101-4tasks-100eps`. The per-episode image standard deviation is 0.0 in every episode, so the
image std in `stats.json` is about 0.01-0.02 instead of a realistic 0.15. This is harmless for policies that do not
normalise images with dataset statistics (smolvla, xvla, pi0, pi05). It is wrong for `multi_task_dit`, which always
normalises images with mean and std, and for `diffusion`; that is why those two stay on `svla`. Under percentile
(QUANTILES) normalisation, used by pi0.5, the open-gripper target lands near +3 (2.95 for action, 3.05 for state; the
maximum sits far above the 99th percentile). The value is finite and maps back to physical units, so training runs. It only
means fully open gripper positions are rare in the data and may be reproduced less accurately.

When one run uses two datasets. `evaluation.heldout` is a single setting shared by every policy, so leave it at `auto`;
explicit episode ids would apply to both datasets. `--require-flat-names` turns the `action.names` warning into a failure.
The pipeline adds it only to the dataset group that contains `groot` or `molmoact2`, the policies whose registry entry sets
`requires_flat_action_names`. Other datasets in the same run are checked without it
([docs/RECORDER_CHECK.md](RECORDER_CHECK.md)). `smoke.reuse` can stay on: a passed smoke test is reused only for the
identical dataset, because a hash of the dataset's files is part of the match.
